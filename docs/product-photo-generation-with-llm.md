# Генерация оформленного фото товара с помощью LLM и референс-изображения

## Цель

На входе — референсное фото товара и данные из формы (название, цена, бренд, характеристики, описание).
На выходе — картинка для карточки товара: само изображение товара + красиво оформленное описание/рекламный текст для интернет-магазина.

## Главный вывод

Не стоит просить LLM «нарисовать картинку с текстом». Даже GPT Image / Gemini Image нестабильно пишут кириллицу, допускают опечатки и могут исказить упаковку товара.

Надёжная схема — разделить процесс на три шага:

1. Референс-фото уходит в vision-модель, которая возвращает **структурированный текст**.
2. При необходимости image-модель генерирует **фон/сцену без текста**.
3. Финальный кадр собирается **детерминированно** через canvas или SVG: фон → товар → текст → цена/бренд.

Так сохраняются точные название, цена и характеристики, но остаётся красивый креатив.

## Возможные решения

| Подход | Как работает | Плюсы | Минусы |
| --- | --- | --- | --- |
| Один image-LLM со всем в промпте | Передаём фото и просим разместить товар на фоне и добавить текст | Один вызов, максимум креатива | Плохая кириллица, опечатки, искажение товара, нестабильность |
| LLM на текст + image-LLM на фон + compositing **(рекомендуется)** | Текст отдельно, фон отдельно, потом соединяем | Точный текст, сохранение товара, красивый фон | 2–3 шага, нужна сборка кадра |
| LLM на текст + готовые шаблоны canvas/SVG |Вообще без генерации изображений, только оформление | Дёшево, быстро, предсказуемо, бренд-консистентно | Нет AI-фона, ограничено шаблонами |
| Cutout товара + генеративный фон | Удаляем фон с референса, генерируем сцену, накладываем товар обратно | Правдоподобный «жизненный» кадр | Нужен background removal и маска, иначе артефакты |

Для интернет-магазина лучше всего подходит комбинация второго подхода с элементами третьего и четвёртого.

## Рекомендуемый пайплайн

### 1. Vision-вызов за текстом

Текущие `generateAnswer` и `localGenerate` принимают только `prompt: string`. Для референс-фото нужен отдельный server action с мультимодальным сообщением: `text + image_url` (data URL или публичный URL).

В `unoRouterModels` уже есть `gpt-4o:free` и `gemini-3.6-flash:free` — они подходят для vision. Локальный `gemma-4`, скорее всего, текстовый, поэтому для этой задачи лучше сделать отдельный `generateVisualCopyAction`.

### 2. Жёсткий контракт ответа

Ответ модели должен валидироваться через zod:

```ts
{
  headline: string,        // до 40 символов
  subheading: string,      // до 80 символов
  benefits: string[],      // 2–3 пункта до 60 символов
  cta: string,             // например, «Подробнее» или «В корзину»
  backgroundPrompt: string,// описание фона БЕЗ текста
  palette: string[]        // 2–3 цвета из референса
}
```

В промпте прямо запрещать выдумывать характеристики и цену: только то, что передано из формы. Текст — на русском, без HTML, без эмодзи по умолчанию.

### 3. Фон

Варианты:

- image-модель генерирует фон по `backgroundPrompt` без какого-либо текста;
- фон не генерируется вообще: из референса берётся палитра и рисуется градиент;
- фон заменяется готовым шаблоном бренда.

Второй вариант часто смотрится чище и почти ничего не стоит.

### 4. Сборка кадра

У проекта уже есть `src/shared/services/canvas/CanvasDraw.ts` с методами `rect`, `image`, `text`. Его можно расширить под word-wrap через `measureText` и собирать кадр 1080×1080 или 1200×900:

1. фон;
2. изображение товара (при необходимости — cutout без фона);
3. заголовок и подзаголовок;
4. список преимуществ;
5. цена, бренд, CTA.

Перед рендером нужно дождаться `document.fonts.ready`, иначе шрифт «прыгнет». Альтернатива — SVG + `sharp` / `resvg-js` на сервере, но тогда нужны локальные файлы шрифтов с кириллицей.

### 5. UI

Логично добавить кнопку «Оформить с AI» в `ProductFormPhotos` / `ProductPhotoPreviewModal`, показывать 2–3 варианта и добавлять выбранный через существующий `uploadPhotoAction`. Оригинальное фото нужно сохранять отдельно, чтобы можно было откатить неудачную генерацию.

### 6. Метаданные генерации

Желательно хранить: `original_photo_id`, `model`, `prompt`, `template_version`, `seed`. Без этого невозможно воспроизвести удачный кадр.

## Возможности удаления фона у товара

- `@imgly/background-removal` — WASM, можно прямо в браузере;
- `rembg` / U2Net — отдельный сервис;
- remove.bg — внешний платный API;
- image-модель с прозрачным фоном — наименее надёжный вариант.

Если референсы уже на белом фоне, можно просто кадрировать товар без background removal.

## Риски и ограничения

- **Текст на изображении** — главный источник брака, поэтому его рисуем сами.
- **Сходство товара** — image-модели меняют этикетки и цвета; безопаснее накладывать оригинальный cutout.
- **Юридические вопросы** — не генерировать логотипы брендов и не приписывать несуществующие свойства.
- **Стоимость и латентность** — vision ~1–3 с, image gen ~5–30 с; нужны pending-состояния, кэш по хэшу `фото + товар` и ограничение частоты вызовов.
- **Размер референса** — перед отправкой в LLM уменьшать примерно до 1024 px и JPEG quality ~80.

## Порядок реализации

1. Server action `generateProductVisualAction(image, productData)`.
2. Vision-вызов и zod-валидация текста.
3. Необязательный image-вызов для фона без текста.
4. Детерминированный render в canvas: фон → товар → текст → цена/бренд.
5. Предпросмотр вариантов в модалке и загрузка выбранного как фото товара.
6. Тесты на кириллицу, длинные названия и падение LLM.

## Принципы

- Разделение генерации контента и рендеринга.
- Детерминизм для текста и цены.
- Сохранение исходного товара без искажений.
- Повторное использование существующих `CanvasDraw` и `uploadPhotoAction`.
- Возможность вернуться к оригинальному фото.
